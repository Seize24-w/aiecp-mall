🌐 **在线体验：<https://seize24-w.github.io/aiecp-mall/>**

## 一、快速开始

```
方式一：直接双击 index.html（推荐，最简单）
方式二：用本地服务器打开（避免个别浏览器对 localStorage 的限制）
        python -m http.server 8080   →   http://localhost:8080
```

## 四、三项 AI 能力的实现要点

### 1. 智能选品（`assets/js/ai.js · Selection`）
- **画像构建**：由浏览 / 加购 / 成交埋点按权重（1 / 3 / 6）回流，输出偏好品类、价格带、活跃度。
- **多路召回**：画像偏好、协同过滤（高销量）、向量语义（价格带相近）、热门新品、场景关联。
- **精排打分**：`0.38×召回权重 + 0.24×热度 + 0.16×评分 + 0.14×价格匹配 + 稳定噪声`。
- **业务规则过滤（BR-09）**：剔除下架、无库存商品。
- **多样性重排（BR-10）**：同一叶子品类占比不超过结果条数的 50%。
- **冷启动兜底**：行为数据 < 3 条时 `degraded=true`，回落热门榜。
- 响应携带 `traceId / strategyCode / experimentTag`，卡片上标注「召回来源」与「推荐理由」。

### 2. 智能组货（`assets/js/ai.js · Bundle`）
- 场景识别（厨房 / 清洁 / 客厅 / 数字生活 / 卧室 / 收纳）→ 配套品类召回 → 库存与预算可行性校验。
- **组合定价在毛利约束下求解**：组合毛利率 `gross(r) = 1 − costEff/(r × origin) ≥ 主商品单品毛利率`，
  取「场景目标折扣」与「毛利红线折扣」中较保守的一个；折扣被收敛时卡片会明确提示。
- **BR-11**：方案须含 ≥ 2 个可售 SKU；**BR-12**：毛利不达标即不输出。
- 无可行方案时 `degraded=true` 并降级为同品类单品推荐（附降级原因）。
- 一键加购保留 `bundleId`，购物车与结算页保留组合标识用于归因（FR-23）。

### 3. 智能客服（`assets/js/ai.js · CustomerService`，右下角悬浮入口）
- 意图识别：物流 / 退换 / 质保 / 支付 / 优惠 / 安装 / 发票 / 库存 / 商品 / 订单查询。
- 知识咨询走 **RAG 检索增强**（8 条知识片段，返回 `citations`）；业务事实走 **受控工具调用**
  （`queryOrder` / `queryMyOrders` / `queryStock`，均声明出入参 Schema）。
- 流式输出（模拟 NFR-03 首字延迟），保留最近 10 轮上下文（BR-14），
  置信度 < 0.65 时携带会话摘要建议转人工（FR-16）。
- 安全护栏：输入侧拦截提示注入 / 越权意图，输出侧弱化绝对化表述（NFR-10）。
- 面板内可一键「模拟大模型故障」，验证 NFR-07 的降级契约。

## 五、如何体验完整交易闭环

1. 首页 → 点击任意商品进入详情，选择规格后「加入购物车」（或体验「一键加购整套」组货方案）。
2. 购物车 → 勾选商品 →「去结算」。
3. 结算页 → 选择/新增地址 → 选优惠券 →「提交订单」。
4. 收银台 →「确认支付」（重复回调不会二次改状态，验证幂等）。
5. 订单详情 →「模拟商家发货」→「确认收货」，观察状态机与物流轨迹变化。
6. 右下角 AI 客服 → 输入 `AIECP20260928001` 体验订单查询工具调用。

## 六、假设与默认方案（成果包未明确之处）

| # | 事项 | 采用的默认方案 |
|---|---|---|
| 1 | 成果包只提供需求/设计文档与 UML，无原型与视觉稿 | 自行设计浅色科技风视觉体系（科技蓝 + AI 紫 + 价格红），并建立设计令牌与响应式断点 |
| 2 | 无真实商品图片 | 用脚本生成本地 SVG 商品图（渐变底 + 品类图形），保证离线可用、无外链 |
| 3 | 成本价未定义，但 BR-12 需要毛利率 | 按零售规律反推：毛利率 `= 18% + 42% × (1 − min(1, 售价/4500))`；组合另计 3% 采购/履约成本节约 |
| 4 | BR-12「组合毛利率不低于主商品单品毛利率」与打折天然冲突 | 改为**在毛利约束下求解最大可给折扣**（折扣自动收敛到红线），并在卡片上提示；毛利无解时不输出方案并降级 |
| 5 | 支付、物流为外部系统 | 用模拟收银台 + 预置物流轨迹代替；倒计时、验签、幂等以提示与逻辑演示 |
| 6 | 商品评价内容缺失 | 只保留评分与评价数，详情页提供「评价」按钮的模拟反馈 |
| 7 | 品类 JSON 规范未定义图标字段 | 扩展 `category.icon`（emoji）作为可选字段，解析器对未知字段「忽略不报错」（符合 NFR-16） |
| 8 | 运费规则未定义 | 默认全场包邮，大家电免运费（业务规则集中在 `Freight.calc`，便于替换） |
| 9 | 自定义品类导入后无商品 | 新品类即时出现在全站导航与列表，无商品时显示空态，不做数据编造 |
| 10 | 鉴权未实现 | `login.html` 为纯模拟，不校验真实密码，仅写入本地昵称与脱敏手机号 |

## 七、测试

```bash
# 1. 逻辑层冒烟测试（无需依赖，46 项断言）
node tools/smoke_test.js

# 2. 真实 DOM 页面测试（需要 jsdom，54 项断言：15 个页面加载 + 交互流程）
npm install jsdom
node tools/dom_test.js
```

覆盖品类域、商品域、购物车与优惠、智能选品、智能组货、智能客服、订单状态机、
品类 JSON 校验器、金额格式化，以及 **15 个页面的加载渲染与「加购 → 加购组货 →
购物车 → 结算 → 下单 → 支付」完整交互流程**，全部通过。

> 测试过程中发现并修复了两个真实缺陷：
> ① 同一秒内创建多笔订单时订单号重复，导致取消/发货操作命中错误订单；
> ② 组货组合价四舍五入后会跌破 BR-12 的毛利率红线（改为向上取整 + 在毛利约束下求解折扣）。
